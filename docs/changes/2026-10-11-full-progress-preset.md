## Implementation
- full_progress.py: sequential stage coordinator, pinned roster, acknowledgement, durable issued/observed receipts, cancellation, explicit closing of stopped receipts, no automatic replay of uncertain stages. A finished run is not saved-character proof.
- full_progress_runtime.py: shared missions; content-filtered discoveries; ready, owned-content travel checkpoints; character/specialization levels; owned vault-card levels and tokens; currency top-ups by current balance; SDU points; applicable vehicle/cosmetic unlocks; queued UVH; existing-access Mayhem; applicable challenges. Requests wait for asynchronous queues and character level/currency readback. Already higher levels/balances are not reduced. SDU points are not a claim that all upgrade purchases are made.
- progress_access.py/full_progress_content.json: current-build DLC access query, same getter used by DLCEntitlementValueResolver, with executable hash validation from MissionRuntime and exact function fingerprints. Definition names and source hashes retained. Actor results cross-check existing reflected mission entitlement attributes.
- full_progress_policy.json: conservative selection policy using extracted challenge stat namespaces/inheritance and curated map identities. This is NOT a recovered native ownership algorithm. Unmapped challenges are skipped, even in an all-content lobby. DLC-specific challenges require access across the bound lobby. Vault-card level/token writes use each player's own entitlement result.
- mission_discovery.py: accepts subsets when each selected child's required parent is included; source order remains intact. Enables withholding unavailable DLC regions.
- backend_actions.py/external_bridge.py: six full_progress routes, competing progress-action exclusion, roster guards for queues, no retry/chunk fallback for uncertain full-progress challenge calls, stop on UVH send failure. Existing standalone challenge retry behavior retained.
- electron_poc/full_progress_panel.js and Missions panel: lobby check, explicit shared-change acknowledgement, one run button, status, stop, close stopped run, coverage and skipped/partial result display.
