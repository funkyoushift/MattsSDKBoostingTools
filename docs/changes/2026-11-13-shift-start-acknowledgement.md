## Follow-up: repeated Start could starve heartbeats

Source review found a separate defect in the acknowledgment repair. Each fresh Start canceled the scheduled one-second heartbeat, sent `start`, then scheduled a new heartbeat after its reply. The native controller accepts an already-owned Start without extending its five-second lease; only `heartbeat` renews that lease. Fresh Start commands arriving more often than the timer could therefore acknowledge successfully while preventing all renewal, eventually expiring the lease.

`tools/afk_lobby/shift_background.js` now sends an immediate heartbeat after validating each repeated-Start acknowledgment. It retains the same page-owned token and endpoint, the initial 150 ms entry delay, readiness and response validation, and native lease duration. A queued Stop takes priority over renewal; canceled generations and invalid responses cannot revive it. No native timeout, cancellation-handler or companion change is part of this repair.

`tools/afk_lobby/test_shift_background.js` now advances a deterministic clock and models the native lease rule. Eighteen fresh Starts at intervals shorter than one second span multiple lease periods; each produces an actual same-token heartbeat, then a later Stop ends traffic. Additional cases cover queued Stop, canceled acknowledgments, wrong token/instance and lost readiness. The regression run against the pre-repair HEAD source fails specifically with `Native lease expired despite successful repeated Starts`; the repaired full JS suite, both JS syntax checks and `git diff --check` pass. These are offline checks, not live qualification of the final PAK.

The historical Windows trialE lease expiry after Close/reopen remains unexplained. The source-supported repeated-Start defect is not proof that trialE had this cause. TrialE recovery and later stable intervals remain valid observations; neither is relabeled as a fix or universal focus-transition pass. A bounded final-candidate lifecycle observation may qualify the new build while retaining this limitation, without repeating Martin's completed physical controls matrix.
