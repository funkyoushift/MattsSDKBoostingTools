Independent review identified and repaired two release blockers before publication. The old Windows helper always used its canonical per-user root, so updating an NSIS/custom/portable install could leave its original launcher stale. New WindowsReleaseUpdater downloads/verifies the NSIS EXE, stages a static PowerShell handoff outside ASAR, passes data as base64 JSON (not interpolated script), waits for app exit, requests native elevation and installs with /D=<actual current executable parent> as the final NSIS argument. Installer failure/UAC cancellation is logged and the existing app is reopened. Native Windows fixture execution is now required in CI. Historical helper remains bundled for compatibility but is no longer the new app updater.

Concurrent checkForUpdates during Linux download could mix release metadata with downloaded bytes. Both platform implementations now guard busy checks, invalidate stale check generations and capture immutable download info; delayed-fetch regression passes.
