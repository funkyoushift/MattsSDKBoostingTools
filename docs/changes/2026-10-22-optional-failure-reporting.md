# Optional private failure reporting — 2026-10-22

## Symptom and cause

Repeated Steam/Epic crash and save-error reports arrived through manual messages with no consistent logs. The existing Report tab only prepared a public GitHub issue draft. It had no private intake, install consent, automatic command-failure signal, or daily review.

## Change

Both the public NSIS installer and the custom Windows setup form now offer an unchecked automatic-reporting choice and a separate unchecked memory-dump choice. The public installer leaves a previous choice intact when the checkbox is untouched. The same choices can be changed in the desktop Report tab; opt-out aborts an active upload where possible, prevents later uploads, and removes queued reports. Automatic updates retain the existing choice. The Electron main process reports failed `/action` game commands (including completed queued replay failures), uncaught desktop errors, renderer termination, and new game crash context found under `Documents/My Games/Borderlands 4/Saved/Crashes`. It checks for crash context at startup and every two minutes. Reports include small, redacted SDK/game log excerpts; they never read SaveGames or serialize command inputs. Raw game minidumps are included only with the second choice. A bounded local outbox retries failed uploads, and duplicate identical command failures are throttled for ten minutes.

The receiver is a separate Cloudflare Worker, `msbt-failure-reports`, accepting bounded JSON at `https://msbt-failure-reports.screename53.workers.dev/v1/reports`. It rate-limits by IP, accepts only fixed report/file types, and caps each day at 200 objects or 256 MiB. R2 bucket `msbt-private-failure-reports` has no public R2 domain and a seven-day deletion rule. A daily 9 AM local heartbeat, `review-msbt-failure-reports-daily`, inspects new private reports and stays quiet on unchanged non-actionable days. The Worker was deployed at version `54ee7740-00f4-41c9-b1bc-eda553f5f2e9` in Cloudflare account `3cf3126cc25a865942d713e956d5244f`.

## Validation and boundaries

Offline: installer .NET build passes; JavaScript syntax, 4 client tests, 4 Worker tests, and 5 Quick Menu/bridge startup checks pass. The source Electron smoke check and the UI/navigation checks in `npm run check` passed through responsive layout. That full check then stopped at `test_bundled_game_install.js` because this isolated checkout lacks the ignored `electron_poc/vendor/oak2/oak2-sdk.zip` fixture; its two remaining AFK/password tests passed separately. An NSIS installer compiled with the consent page and uses the existing run-as-user helper to save the choice in the player's profile. This isolated package lacks the ignored bundled setup, Python and SDK assets and is not a valid release candidate. `wrangler deploy --dry-run` validated R2 and rate-limit bindings. Live receiver: invalid JSON returned 400; a synthetic valid report returned 202, appeared in private R2, was readable through authenticated Cloudflare access, and was deleted. Managed/public R2 domain is disabled and no custom domain exists. The app has not been installed or tested with an opted-in real game failure; no customer report has been received through this feature. Steam/Epic save-error or game-crash root cause is still unresolved. When the desktop app is not running, SDK-only commands cannot send a failure immediately; game crash context is scanned next time the app starts. Electron native memory dumps are not collected. The run-as-user install handoff still needs a real installer test before release.

## Deployment and rollback

The Worker and R2 bucket are live. Martin authorized a v2.39.5 patch release. The official Windows, full SDK, standalone selector and unchanged Android packages have been built and checked; publication state is recorded in `docs/releases/VERIFICATION_v2.39.5.txt`. The packaged reporting helper accepted logs-only consent, then its newly written normal-profile preference was disabled and verified off. The NSIS run-as-user handoff and an actual opted-in game failure still need live verification. To stop intake, disable/delete the Worker trigger; to stop clients, disable reporting in the Report tab or installer. Preserve private R2 data only within the seven-day retention window. No save files were edited or collected.
